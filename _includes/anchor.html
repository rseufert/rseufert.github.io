{%- comment -%} Chrome on an iPhone, sent straight to a part of a page (/#projects, a link from another page or another app), lands there and then keeps the top of the page under its own toolbar: the menu cannot be scrolled back to. It is Chrome's fault and only Chrome's; Safari on the same phone is fine, and so is a jump made from inside the page once it has loaded. So, in that browser only, the arrival is made to look like the second case. This is the last script on the page, so everything above has read the address already and every element is there to be found. If the hash names an element, it is taken off the address before the browser acts on it, the page loads at its top, and then the page scrolls to the element itself and the hash goes back where it was. A hash that names no element (a game's seed, rickbot's #chat) is left alone, and a visitor who has already touched the page is not moved. {%- endcomment -%}
